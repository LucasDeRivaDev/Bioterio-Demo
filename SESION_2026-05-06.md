## ✅ Qué se hizo

### 1. Auditoría del proyecto
- Se revisaron todos los archivos en busca de errores, imports sin usar y assets innecesarios
- Se eliminaron `react.svg` y `vite.svg` (placeholders por defecto de Vite, no se usaban en ningún componente)

### 2. Fix: BIO hardcodeado en Stock.jsx y Camadas.jsx
**El problema:** Dos páginas importaban la constante `BIO` directamente desde `constants.js`, que siempre tiene los parámetros de rata. Eso significa que si el usuario elegía cobayo (gestación 65 días), la app igual usaba 23 días (rata) para clasificar los animales.

**La solución:** Se cambió para que usen `bio` del contexto (`useBioterio()`), que sí respeta la especie elegida por el usuario.

Archivos modificados:
- `src/pages/Stock.jsx` — función `categoriaStock`, y cálculos de destete y madurez en `datosResumen`
- `src/pages/Camadas.jsx` — auto-separación de pareja y etiqueta de días post-cópula

### 3. Tutorial interactivo (11 pasos)
Se creó `src/pages/Tutorial.jsx` con:
- 11 pasos que explican toda la app (especie, dashboard, reproductores, camadas, stock, calendario, rendimiento, estadísticas, temperatura, incidentes, reportes)
- Barra de progreso animada con color dinámico según el paso
- Puntos de navegación clickeables para saltar a cualquier paso
- Índice completo abajo con checkmarks de pasos completados
- Botones Anterior / Siguiente — el último botón dice "Ir al panel" y redirige al Dashboard
- Botón "Saltar tutorial" para quien ya lo conoce

También se agregó:
- Ruta `/tutorial` en `AppPro.jsx`
- Link **"Tutorial"** con ícono de libro en el `Sidebar.jsx`

### 4. Renombrado Pro → Demo
Se cambió todo lo que decía "Pro" o "BioteríoPro" por "Demo" o "BioteríoDemo":

| Archivo | Qué cambió |
|---|---|
| `index.html` | Título de la pestaña del navegador |
| `AppPro.jsx` | Badge `PRO` → `DEMO` en topbar móvil |
| `Sidebar.jsx` | Badge `Pro · LOCAL` → `Demo · LOCAL` |
| `FormularioEspecie.jsx` | Logo `BioterioDemo` |
| `Tutorial.jsx` | 5 ocurrencias de `BioteríoPro` → `BioteríoDemo` |

> ⚠️ El cambio de keys de localStorage hace que los datos anteriores se pierdan — la app arranca como si fuera la primera vez. Es el comportamiento esperado en una demo.

## 🧠 Conceptos aprendidos

- **Auditar un proyecto React:** cómo buscar imports sin usar, assets sin referencias, y constantes hardcodeadas con grep
- **BIO del contexto vs constants.js:** si la constante viene hardcodeada, ignora la especie que eligió el usuario. Siempre hay que usar el `bio` que viene del contexto (`useBioterio()`)
- **Dependencias de useMemo:** toda variable que se use dentro del cálculo tiene que estar en el array de dependencias `[]`. Si no está, React no recalcula cuando esa variable cambia
- **Tutorial paso a paso:** se puede construir con un simple `useState` para el índice del paso actual, y los pasos como un array de objetos con título, ícono y contenido JSX
- **Keys de localStorage:** renombrarlas es como empezar de cero — los datos guardados bajo el nombre viejo no se migran solos
